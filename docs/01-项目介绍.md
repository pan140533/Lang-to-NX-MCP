# Lang-to-NX MCP — 项目介绍

> 版本: v0.1 | 更新: 2026-06-25

---

## 一、项目定位

**Lang-to-NX MCP** 是一个让通用 AI Agent（如 Claude、Cursor 等）能直接操控 Siemens NX 建模的 MCP（Model Context Protocol）服务器。

它解决的根本问题是：

```
NX 是闭源 CAD 软件，AI 无法直接操作其内部 3D 几何数据。
唯一入口是 NXOpen API（二次开发接口），而 NXOpen API 本身就是
人类 CAD 操作的编程封装——草图、拉伸、旋转、阵列。

→ 让 AI 扮演一个"会写 NX 二次开发脚本的人"
```

---

## 二、核心设计原则

### 原则 1：外部进程执行，NX 不常驻

```
✅ 方案：run_journal.exe（外部进程）
  AI → MCP Server → 生成 C# → subprocess → run_journal.exe → NX（用完即退）

❌ 不采用：Python NXOpen API（进程内）
  AI → Python NXOpen API → NX 进程内执行（NX 必须一直开着）
```

**原因：**
- **批量建模**需要 NX 用完即退，不占 License
- NX 本身是大进程，在里面跑重型 Python 逻辑不合适
- 进程隔离——C# 崩了不影响主进程，subprocess 重启就好

### 原则 2：MCP 协议，通用接入

所有 NX 建模能力封装为标准 MCP 工具，任何支持 MCP 协议的 AI Agent 都可以直接调用：
- **Claude Desktop**（通过 MCP 配置）
- **Cursor** 等 IDE
- 自定义 Agent

### 原则 3：分层架构

```
第1层: AI Agent 层
  通用 AI Agent（Claude / Cursor / 任何 MCP Client）
  理解用户意图、规划建模步骤、调用 MCP 工具
       │ MCP 协议 (stdio)
       ▼
第2层: MCP 协议层（Python 薄层）
  工具注册 / 参数校验 / 错误格式化
  不涉及任何 CAD 操作，只做协议转换
       │
       ▼
第3层: C# Journal 层
  generator.py 将 JSON 步骤转为 C# 代码
  nx_modeler.cs 封装 NXOpen API 调用
       │ subprocess
       ▼
第4层: NX 执行层
  run_journal.exe 编译执行 C# 脚本
  输出 .prt 3D 模型文件
  进程用完即退
```

## 三、数据流

```
用户输入："创建一个三叶风扇"
    │
    ▼
AI Agent 理解意图 → 规划步骤 → 调用 MCP 工具
    │
    ▼
nx_execute_plan({
  steps: [
    {"tool": "cylinder", "params": {"radius": 30, "height": 20}},
    {"tool": "create_sketch_on_plane", "params": {}},
    {"tool": "draw_rectangle", "params": {"x": -10, "y": 0, "width": 20, "height": 80}},
    {"tool": "close_sketch", "params": {}},
    {"tool": "extrude", "params": {"length": 5}},
    {"tool": "pattern_circular", "params": {"count": 3, "angle": 360}},
  ]
})
    │
    ▼
JournalGenerator.generate(steps)
  → 生成完整的 C# Journal 脚本
    │
    ▼
保存 .cs 文件 → subprocess → run_journal.exe
    │
    ▼
NX 执行建模 → 输出 .prt 文件 → 返回路径给 AI
```

## 四、技术栈

| 层级 | 技术 | 用途 |
|------|------|------|
| AI 协议层 | **MCP Python SDK** (mcp>=2.0.0) | MCP 服务器、工具注册、参数校验 |
| 代码生成 | **Python 3.10+** | generator.py 将 JSON 步骤转为 C# |
| C# 执行 | **C# 5.0** + **NXOpen API** | nx_modeler.cs 封装 NX API 调用 |
| NX 引擎 | **Siemens NX**（上游开发用 2412；当前部署 NX 11.0） | CAD 建模引擎 |
| 执行器 | **run_journal.exe** | NX 自带的 C# Journal 执行器 |
| 可选: API | **FastAPI + Uvicorn** | 前端 HTTP 接口（规划中，尚未实现） |

> **版本说明**：上游项目基于 NX 2412 开发，本 checkout 部署在 NX 11.0；
> MCP SDK 需 2.x（`server.py` 用 2.x 的回调式注册，1.x 的装饰器 API 已被移除）。
> 详见 [03-技术规范.md](./03-技术规范.md) 开头的环境版本说明。

## 五、与同类项目的关系

### NX_MCP（参考项目）

| 维度 | NX_MCP | Lang-to-NX MCP |
|------|--------|----------------|
| MCP 协议层 | ✅ Python MCP Server | ✅ 移植了同样的协议层 |
| 执行方式 | ❌ Python NXOpen API（进程内） | ✅ C# Journal + run_journal.exe（进程外） |
| NX 运行状态 | 必须一直打开 | 用完即退，适合批量 |

**NX_MCP 在本项目中的角色**：提供了 MCP 协议层的参考实现（server.py、registry.py、response.py），但其执行方式（Python NXOpen API 进程内调用）不符合本项目的批量建模需求，故不采用。

### Lang-to-NX（前身项目）

| 维度 | Lang-to-NX | Lang-to-NX MCP |
|------|------------|----------------|
| Agent 管线 | ✅ 内置（intent→decompose→plan→execute） | ✅ 可复用，也可由通用 AI Agent 替代 |
| 前端 | ✅ Next.js + Three.js | ✅ 后续移植 |
| MCP 协议 | ❌ 无 | ✅ 标准 MCP 协议，通用接入 |
| 执行方式 | C# Journal + run_journal.exe | ✅ 继承并改进 |

**本项目是 Lang-to-NX 的 MCP 化架构升级**，保持其外部进程执行方式，增加 MCP 协议层使其能被任何通用 AI Agent 调用。

## 六、适用场景

| 场景 | 说明 |
|------|------|
| ✅ **批量建模** | 一次性生成大量模型文件，调用 run_journal.exe 用完即退 |
| ✅ **AI 驱动设计** | Claude 等 AI Agent 理解自然语言需求后自动建模 |
| ✅ **CI/CD 集成** | 在自动化流水线中调用 NX 生成模型 |
| ✅ **二次开发封装** | 将 NX 能力封装为标准化 API 供上层调用 |
| ❌ **交互式建模** | 需要实时操作 NX 界面的场景（建议用 NX_MCP） |
