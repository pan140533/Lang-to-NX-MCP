## 一、整体架构（双路径设计）

本系统支持**两条并行路径**，共享同一套底层执行引擎：

```
用户输入（自然语言："创建一个三叶风扇"）
    │
    ├──[路径A]──────────────────────────────────────────────┐
    │  AI Agent 直达模式                                     │
    │  适合: 开发者 / 高级用户 / 批量建模                    │
    │  工具: Claude Desktop, Cursor, 任何 MCP Client         │
    │                                                        │
    │  用户 ↔ AI Agent (Claude)                              │
    │              │                                         │
    │              ├─ 理解意图、规划步骤                      │
    │              ├─ 调 MCP 工具 (nx_execute_plan)           │
    │              └─ 返回 .prt 文件路径                     │
    │                                                        │
    └──[路径B]──────────────────────────────────────────────┐
      Web 网页模式                                           │
      适合: 普通用户 / 不想接触命令行的用户                  │
      工具: 浏览器访问 http://localhost:3000                  │
                                                             │
      用户 → Web 前端 (Next.js + Three.js)                    │
                  │                                          │
                  ├─ 输入框 / 历史记录 / 3D 预览             │
                  ├─ HTTP POST → FastAPI 后端                  │
                  │                                          │
                  ▼                                          │
              FastAPI 后端                                    │
                  │                                          │
                  ├─ 调用 AI Agent API (DeepSeek/Claude)      │
                  │   → LLM 理解意图 + 生成建模计划           │
                  ├─ 执行建模 (MCP Server / 直接 executor)    │
                  │   → 生成 C# Journal → run_journal.exe     │
                  ├─ 返回结果                                 │
                  └─ Three.js 3D 预览                         │
```

**关键原则：两条路径共享同一套执行引擎。** 无论是 AI Agent 直接调用，还是 Web 端触发，最终都走同一条路：

```
自然语言 → AI 理解 → 结构化步骤 → C# Journal → run_journal.exe → NX → .prt
```

## 三、双路径详细数据流

### 路径A：AI Agent 直达模式

```
用户 (命令行/Claude Desktop)
  │  "给我创建一个三叶风扇"
  ▼
Claude Desktop (AI Agent)
  │  1. 理解用户意图
  │  2. 规划建模步骤
  │  3. 调用 MCP 工具 nx_execute_plan
  │
  ├── MCP Protocol (stdio) ──→ MCP Server
  │                               │
  │                               ├── 接收步骤列表
  │                               ├── JournalGenerator.generate()
  │                               ├── 保存 .cs 文件
  │                               ├── subprocess → run_journal.exe
  │                               ├── NX 执行 → 输出 .prt
  │                               └── 返回 .prt 路径
  │
  └── 用户收到: 模型已创建，文件在 output/models/xxx.prt
```

**特点：**
- 用户直接和 AI Agent 对话，体验最自然
- 适合开发者、批量建模、CI/CD 集成
- 需要用户自行配置 MCP Client（如 Claude Desktop）

### 路径B：Web 网页模式

```
用户 (浏览器)
  │  "创建一个三叶风扇"
  ▼
Web 前端 (Next.js + Three.js)
  │  POST /api/command { description: "三叶风扇" }
  ▼
FastAPI 后端
  │
  ├── 1. 调用 AI Agent API (DeepSeek/Claude)
  │      → 意图识别: 创建
  │      → 结构分解: 中心圆柱 + 叶片阵列
  │      → 步骤规划: cylinder → sketch → extrude → pattern_circular
  │
  ├── 2. 执行建模
  │      → 调用 MCP Server (内部 subprocess/直接调用)
  │      → JournalGenerator.generate(plan_steps)
  │      → run_journal.exe → .prt
  │
  ├── 3. 返回结果
  │      {
  │        status: "success",
  │        features: [{type: "cylinder", ...}, {type: "block", ...}],
  │        part_path: "output/models/xxx.prt",
  │        human_thought: "这是一个三叶风扇，中间是圆柱..."
  │      }
  │
  └── Web 前端
      ├── Three.js 根据 features 渲染 3D 预览
      ├── 聊天框显示 AI 的思考过程
      └── 特征列表显示所有建模步骤
```

**特点：**
- 用户通过浏览器操作，无需任何配置
- 内置 3D 预览（Three.js），即时看到结果
- 同样经过 AI Agent 解析，智能程度不降级

## 四、各层详解

### 4.1 前端层 (Frontend)

```
技术选型:
  Next.js 14 + TypeScript     ← 应用框架
  React Three Fiber           ← 3D 渲染
  Tailwind CSS                ← 样式
  three-bvh-csg               ← 客户端布尔运算（预览用）

页面布局:
  ┌─────────────────────────────────────────────┐
  │  侧边栏 (会话历史)  │  3D预览区  │  AI 聊天  │
  │                    │  (Three.js) │ 输入框    │
  │  - 历史会话列表     │  视角控制    │ 消息记录  │
  │  - 特征列表        │  缩放/旋转  │ 思考过程  │
  └─────────────────────────────────────────────┘

3D 预览坐标映射:
  NX 坐标系: X=右, Y=前, Z=上
  Three.js:  X=右, Y=上, Z=前 (渲染时转换)

渲染模式:
  1. 独立特征渲染 (每个特征独立显示)
  2. CSG 布尔运算 (合并/减去/相交)
  3. 回退: CSG 失败时用独立模式
```

### 4.2 后端 API 层 (Backend API)

```
路由设计:
  POST   /api/command          执行建模指令
  POST   /api/session/new      创建新会话
  GET    /api/sessions         获取会话列表
  GET    /api/session/{id}     获取会话详情

核心处理流程 (路径B):
  POST /api/command
  1. 解析请求 { description, session_id }
  2. 调用 AI Agent API 解析自然语言 → 结构化步骤
  3. 通过执行引擎建模
  4. 返回特征列表 + 模型路径 + AI 思考过程

AI Agent 调用:
  LLM: DeepSeek / Claude API
  输入: 用户的自然语言描述
  输出: 结构化建模步骤
  prompt: 包含所有可用工具的 JSON Schema 描述
```

### 4.3 AI Agent 层

```
路径A: 外部 AI Agent (Claude Desktop)
  - 用户自行配置 MCP 连接
  - AI Agent 直接理解、规划、调用 MCP 工具
  - 不经过本系统的后端

路径B: 内部 AI Agent 集成
  - 通过 FastAPI 后端调用 LLM API
  - Agent Pipeline 包含:
    1. 意图识别 (CREATE / MODIFY / QUERY / DELETE / ANALYZE / CHAT)
    2. 结构分解 (阵列/镜像/旋转体/堆叠等7种策略)
    3. 步骤规划 (确定先后顺序和参数)
    4. 参数补全 (LLM 补全默认值)
  - 输出: 结构化步骤列表 → 执行引擎

两种路径的 AI 理解能力应当保持一致。
```

### 4.4 MCP 协议层 (MCP Server)

```
传输方式: stdio (标准输入输出)
协议版本: MCP 1.0+

核心机制:
  工具注册:
    @mcp_tool(name, description, params)
    async def nx_execute_plan(steps) -> ToolResult
      ↓
    ToolRegistry.register(_ToolDef)
      ↓
    server.list_tools() → 返回所有工具的 JSON Schema

  工具调用:
    server.call_tool() → handler(**arguments)
      ↓
    handler 内部:
      1. 构建步骤列表
      2. JournalGenerator.generate(steps) → C# 代码
      3. 保存 .cs 文件
      4. subprocess → run_journal.exe
      5. 返回 ToolResult

  工具列表 (将逐步扩展):
    ⭐ nx_execute_plan   核心: 执行一组建模步骤
    nx_validate_plan     验证步骤合法性
    nx_create_block      创建方块
    nx_create_cylinder   创建圆柱
    nx_create_cone       创建圆锥
    nx_create_sphere     创建球体
    nx_create_torus      创建圆环
    ... (更多工具)
```

### 4.5 C# 执行层 (Journal Generator + nx_modeler.cs)

```
JSON → C# 转换:
  输入:
    [{"tool": "block", "params": {"length": 100, "width": 80, "height": 60}}]

  生成器: generator.py → 调用 _gen_block(params)
    → 返回字符串: 'm.Tool_Block(0.0, 0.0, 0.0, 100.0, 80.0, 60.0);'

  完整脚本结构:
    using System;
    using System.Collections.Generic;
    using NXOpen;
    using NXOpen.Features;
    using NXOpen.GeometricUtilities;

    public class NXJournal {
      public static void Main(string[] args) {
        NXModeler m = new NXModeler();
        m.Init();
        m.Tool_Block(...);   // ← 生成的调用
        m.Tool_SaveModel(...);
      }
    }

    // nx_modeler.cs 的内容（实际的 NXOpen API 实现）
    public class NXModeler {
      public void Tool_Block(double x, double y, double z, double l, double w, double h) {
        // NXOpen API 调用
      }
    }

  nx_modeler.cs 约束:
    - C# 5.0 语法（run_journal.exe 的编译器限制）
    - 不支持 $"" 字符串插值
    - 文件保存为 UTF-8 BOM 编码
```

### 4.6 NX 执行层 (run_journal.exe)

```
执行方式:
  subprocess.run(
    [run_journal.exe, journal.cs],
    capture_output=True,
    timeout=180,
    encoding="gbk"
  )

生命周期:
  启动 → 编译 C# → 连接 NX License → 执行建模 → 保存 .prt → 退出
  (整个过程是一个独立进程，不占用 NX 主程序)

输入:
  .cs 文件 (C# Journal 脚本)

输出:
  .prt 文件 (NX 3D 模型)
  控制台输出 (建模日志)

路径配置:
  NX_ROOT=C:\Program Files\Siemens\NX
  RUN_JOURNAL_EXE=%NX_ROOT%\NXBIN\run_journal.exe
```

## 五、层间接口规范

### 5.1 前端 → 后端 (HTTP)

```json
POST /api/command
Request:
{
  "session_id": "abc123",        // 可选，不传则创建新会话
  "description": "三叶风扇"      // 用户输入
}

Response:
{
  "status": "success",
  "session_id": "abc123",
  "message": "模型已生成",
  "features": [
    {
      "feature_id": "feat_001",
      "type": "cylinder",
      "parameters": {"diameter": 60, "height": 20},
      "position": {"x": 0, "y": 0, "z": 0},
      "boolean_op": "create"
    }
  ],
  "part_path": "output/models/xxx.prt",
  "human_thought": "这是一个三叶风扇...",
  "steps_count": 5
}
```

### 5.2 后端 → MCP Server (内部调用)

```python
# 直接调用 executor (不经过 stdio, 减少协议开销)
from backend.mcp.executor import execute_journal
from backend.journal.generator import JournalGenerator

steps = [
    {"tool": "cylinder", "params": {"radius": 30, "height": 20}},
    {"tool": "create_sketch_on_plane", "params": {}},
    {"tool": "draw_rectangle", "params": {...}},
]
gen = JournalGenerator(tag="fan")
code = gen.generate(steps)
result = execute_journal(code, tag="fan")
```

### 5.3 MCP Server → AI Agent (MCP 协议)

```
AI Agent (Claude Desktop)                  MCP Server
       │                                        │
       │──── JSON-RPC (list_tools) ────────────→│
       │←─── Tool[] (JSON Schema) ─────────────│
       │                                        │
       │──── JSON-RPC (call_tool, nx_execute) ─→│
       │←─── TextContent (执行结果) ────────────│
```

### 5.4 后端 → NX (subprocess)

```
subprocess.run(
  [run_journal.exe, "path/to/journal.cs"],
  capture_output=True,
  timeout=180,
  encoding="gbk"
)
```

## 七、关键设计决策记录

### 7.1 为什么用 C# Journal + run_journal.exe，而不是 Python NXOpen API？

```
❌ Python NXOpen API（进程内）:
  优点: 响应快、可交互
  缺点:
    - NX 必须一直打开（占用 License）
    - NX 进程内跑 Python 重型逻辑不稳定
    - 不适合批量建模

✅ C# Journal + run_journal.exe（进程外）:
  优点:
    - NX 用完即退，不占 License
    - 进程隔离，崩了不影响主系统
    - 适合批量/自动化场景
  缺点:
    - 每次执行有进程启动开销
    - C# 5.0 编译器限制（不支持 $"" 等语法）
    - UTF-8 路径需要特殊处理
```

### 7.2 为什么同时支持 AI Agent 和 Web 两种路径？

```
两种模式覆盖不同用户群:

  AI Agent 模式 (路径A):
    - 面向: 开发者、技术用户、批量模型生成
    - 体验: 命令行对话，直接
    - 优势: 灵活、可编程、可集成到 CI/CD

  Web 模式 (路径B):
    - 面向: 普通用户、非技术用户
    - 体验: 图形界面，直观
    - 优势: 零配置、3D 预览、历史记录

  两者不互斥，共享底层引擎。
  Web 模式的后端同样调用 AI Agent API 进行自然语言理解。
```

### 7.3 为什么 MCP 工具 handler 不走 MCP 协议而是直接调用 executor？

```
路径B (Web → FastAPI → 建模) 需要执行效率。
如果 Web 请求也要经过完整的 MCP stdio 协议，会多一层序列化开销。

因此:
  - 路径A (外部 AI Agent): 通过 MCP stdio 协议调用
  - 路径B (Web): FastAPI 后端直接调用 executor.py 的 Python API

两种路径最终执行的是同一套 JournalGenerator + execute_journal。
```

| 概念 | 规则 | 示例 |
|------|------|------|

| 环境变量 | 大写蛇形 | `NX_ROOT`, `RUN_JOURNAL_EXE` |
