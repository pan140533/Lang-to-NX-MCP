# 技术规范

> 统一 tools.json / generator.py / nx_modeler.cs 三层的参数命名和调用标准
> 版本: v0.1 | 最后更新: 2026-06-20

---

## 一、三层架构概述

```
tools.json             ← 工具清单定义（给 LLM / 开发者看的）
    ↓
generator.py           ← _gen_xxx 方法（JSON 参数 → C# 代码字符串）
    ↓
nx_modeler.cs          ← Tool_Xxx 方法（C# NXOpen API 实现）
```

**数据流：** `tools.json` 的参数名 → `generator._gen_xxx()` 提取参数 → 拼接 `Tool_Xxx()` 调用字符串 → `nx_modeler.cs` 执行

## 二、参数命名规范

### 2.1 基本原则

**参数名三层必须一致**（tools.json ↔ generator ↔ nx_modeler.cs），不准各自起名。

例外：tools.json 允许用 `snake_case` 做可选别名，但 generator 和 nx_modeler.cs 不认别名。

### 2.2 保留字段名

| 概念 | 统一字段名 | 类型 | 说明 |
|------|-----------|------|------|
| X 坐标 | `x` | number | 单位:mm |
| Y 坐标 | `y` | number | 单位:mm |
| Z 坐标 | `z` | number | 单位:mm |
| 长度 | `length` | number | 单位:mm |
| 宽度 | `width` | number | 单位:mm |
| 高度 | `height` | number | 单位:mm |
| 半径 | `radius` | number | 单位:mm |
| 直径 | `diameter` | number | 单位:mm |
| 深度 | `depth` | number | 单位:mm |
| 厚度 | `thickness` | number | 单位:mm |
| 角度 | `angle` | number | 单位:度 |
| 数量 | `count` | number | 纯数量 |
| 间距 | `spacing` | number | 单位:mm |
| x方向间距 | `spacing_x` | number | 单位:mm |
| y方向间距 | `spacing_y` | number | 单位:mm |
| 因子/比例 | `factor` | number | 纯数值（scale用） |
| 起始 | `start` | number | 单位:mm |
| 偏移量dx | `dx` | number | 单位:mm |
| 偏移量dy | `dy` | number | 单位:mm |
| 偏移量dz | `dz` | number | 单位:mm |
| 面索引 | `face_index` | int | 从0开始 |
| 边索引数组 | `edge_indices` | int[] | 从0开始 |
| 布尔操作类型 | `boolean_op` | string | `create`/`unite`/`subtract`/`intersect` |
| 镜像平面 | `mirror_plane` | string | `XY`/`YZ`/`XZ` |

### 2.3 禁止的做法

| ❌ 错误 | ✅ 正确 |
|---------|---------|
| tools.json 叫 `major_radius`，generator 读 `major_radius`，nx_modeler.cs 参数名 `majorR` | 三层统一叫 `major_radius`，generator 读 `major_radius`，映射时传 `majorR` 只是变量名不同 |
| tools.json 里 sphere 定义了 `x`/`y`/`z`，但 Tool_Sphere 根本不收 | 要么 tools.json 删掉 xyz，要么 nx_modeler.cs 加上 xyz 参数 |
| frontend 期待 `base_diameter`，后端返回 `radius` | 统一用 `radius`，前端自己乘以2显示 |

## 三、工具状态规范

每个工具在 tools.json 中必须标注 `status` 字段：

| status 值 | 含义 | 行为 |
|-----------|------|------|
| `implemented` | 已实现并通过测试 | 正常使用 |
| `partial` | 部分实现或有bug | 可以使用但结果可能异常 |
| `todo` | 未实现 | JIT收到调用 -> 日志记录但不崩溃 |

### 示例

```json
{
  "name": "sphere",
  "status": "implemented",
  "params": {"radius": {"type": "number", "description": "半径 (mm)"}}
}
```

```json
{
  "name": "sweep",
  "status": "todo",
  "params": {...}
}
```

## 四、generator.py 编写规范

### 4.1 _gen_xxx 方法的职责

只做 **参数提取 + 字符串拼接**，不做逻辑判断。所有参数用 `.get()` 提取，有默认值的按 tools.json 默认值走。

```python
# ✅ 正确的写法
def _gen_cylinder(self, p: dict) -> str:
    x = p.get("x", 0.0)
    y = p.get("y", 0.0)
    z = p.get("z", 0.0)
    r = p.get("radius", 25.0)
    h = p.get("height", 50.0)
    return f"    m.Tool_Cylinder({float(x)}, {float(y)}, {float(z)}, {float(r)}, {float(h)});"
# 参数名 x/y/z/radius/height 必须和 tools.json / nx_modeler.cs 一致
```

```python
# ❌ 错误的写法
def _gen_sphere(self, p: dict) -> str:
    # tools.json 定义了 radius，没定义 x/y/z，但这里用了 x/y/z
    # Tool_Sphere 只接受 radius
    return f"    m.Tool_Sphere({x}, {y}, {z}, {r});"  # 编译错误！
```

### 4.2 参数顺序必须与 nx_modeler.cs 一致

| tools.json params 顺序 | generator 提取顺序 | nx_modeler.cs 参数顺序 |
|------------------------|--------------------|----------------------|
| x, y, z, radius, height | x, y, z, radius, height | `Tool_Cylinder(x, y, z, r, h)` |

**禁止修改参数顺序。**

## 五、nx_modeler.cs 编写规范

### 5.1 方法签名规范

```csharp
// 参数顺序必须与 tools.json / generator.py 一致
// 参数类型：double radius 对应 "number"；int count 对应 "int"；string 对应 "string"
// 方法名：Tool_UppercaseNamed(...)
public void Tool_Cylinder(double x, double y, double z, double r, double h)
```

### 5.2 Body 追踪规则

```csharp
// 每次创建新体前，把旧体保存
_lastFeature = f if f is Feature;  // 追踪特征（用于阵列）
if (f.GetBodies().Length > 0) {
    _previousBody = curBody;       // 保存旧体（用于布尔）
    curBody = f.GetBodies()[0];    // 更新当前体
}
```

### 5.3 错误处理规则

```csharp
// 复杂方法用 try/catch，打印错误但不扔异常
try {
    // ... API 调用 ...
} catch (Exception ex) {
    Console.WriteLine("[!] MethodName failed: {0}", ex.Message);
}

// 简单方法（有标准API的）直接调用，不用 try/catch
```

## 六、前端数据规范

后端返回的 features 数组必须与前端 Three.js 组件接受的参数一致：

| 类型 | 后端返回 | 前端接收 |
|------|---------|---------|
| block | `{type:"block", parameters:{length,width,height}, position:{x,y,z}}` | `{type:"block", parameters:{length,width,height}}` 前端计算位置 |
| cylinder | `{type:"cylinder", parameters:{diameter,height}, position:{x,y,z}}` | `{type:"cylinder", parameters:{diameter,height}}` |
| cone | `{type:"cone", parameters:{radius,height}}` | 改用 `radius`，前端渲染时乘2显示直径 |
| sphere | `{type:"sphere", parameters:{diameter}}` | `diameter=radius*2` |
| torus | `{type:"torus", parameters:{major_radius,minor_radius}}` | 需要前端实现 Torus 组件 |

**原则：后端传原始参数，前端负责显示适配。** 不在后端做单位转换或直径↔半径换算。

## 七、name_mapper 使用规范

文件名只允许 ASCII 字符（避免 run_journal.exe 编码问题），中文名存到 SQLite 映射表。

```python
# 生成文件名：年月日_标签_序号
def generate_output_name(description: str, index: int = 0) -> str:
    timestamp = now.strftime("%Y_%m_%d_%H_%M")
    tag = extract_ascii_tag(description) or md5_short(description)
    return f"{timestamp}_{tag}_{index}"

# 中文名存入映射表
name_mapper.save(output_name, project_name, description)
```

文件系统：`2026_06_20_12_49_3Yfan_0.cs`
前端显示：`给我一个三叶风扇`

## 九、常见错误排查

### 参数不匹配时的排查流程

```
1. tools.json 定义了哪些参数？
   ↓ 不一致
2. generator._gen_xxx() 提取了哪些参数？
   ↓ 不一致
3. nx_modeler.cs Tool_Xxx() 接受哪些参数？
   ↓
4. 找到差异 → 按"第三层为准"原则统一
```

### "编译失败"常见原因

| 错误信息 | 原因 | 修复 |
|---------|------|------|
| "方法没有采用 X 个参数的重载" | generator 生成的参数数量和 nx_modeler.cs 的不一致 | 数参数个数，对齐 |
| "无法将 string 转换为 double" | 参数类型不匹配 | 检查 .get() 的类型 |
| "文件打开失败" + 乱码路径 | 文件名含中文，run_journal.exe 编码不支持 | 中文名走 name_mapper |
